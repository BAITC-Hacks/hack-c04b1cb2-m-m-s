# Проверка ошибки по горизонту выпуска

Скрипт дополнительно оценивает прогнозы каждого выпуска ECMWF 15–31 января 2026 отдельно для lead time 0–23 и 24–47 часов. Используется одна и та же исходная кривая мощности, обученная по CSV не позднее 31 декабря 2025 года. Для сравнения берётся уже сохранённая поправка ветра ×1,10, ранее выбранная на 1–14 января; скрипт не подбирает параметры повторно. Значения факта и ошибок по отдельным часам не сохраняются.

Часовой пояс CSV в исходных материалах не установлен. Сопоставление использует гипотезу `CSV local − UTC = +5 часов`; это предположение, а не подтверждённая зона. Во втором горизонте доступно 16 выпусков, в первом — 17. Число и состав issue/target пар между горизонтами различаются из-за границ фактических данных. Внутри каждого горизонта baseline и calibrated сравниваются на одинаковых парах «выпуск–час цели».

До расчёта проверяется наличие всех 34 файлов погодного кеша для 15–31 января и обеих турбин. При нехватке хотя бы одного файла скрипт останавливается до чтения погодных данных и не запрашивает сеть. `retrieve` затем проверяет архивную погоду, координаты, единицы, время выпуска и 48 часов. Используется стандартный профиль конкурса из `forecast_weather.LOCATIONS`.

Запуск из корня репозитория:

```sh
python3 experiments/lead_time_check/check.py \
  --input-dir /path/to/originals \
  --cache-dir weather-cache \
  --output predictions/lead-time-validation.json
```

`--input-dir` обязателен и должен содержать `turbine-1.csv` и `turbine-2.csv`. Все метрики нормализованной активной мощности безразмерны. Это holdout-проверка январских архивных прогнозов; она не устанавливает февральскую точность и не заменяет ранее опубликованные общие январские метрики.
