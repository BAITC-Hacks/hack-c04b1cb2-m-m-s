# Walkthrough: ход работы и демонстрация

Время указано по Астане (UTC+5), 23.09.2026. Этот файл дополняется по мере работы; подробные проверки — в [docs/PROGRESS.md](docs/PROGRESS.md), источники — в [docs/SOURCES.md](docs/SOURCES.md). Основной репозиторий: [BAITC-Hacks/hack-c04b1cb2-m-m-s](https://github.com/BAITC-Hacks/hack-c04b1cb2-m-m-s).

## Первый час, 13:00–14:00

**Показуемый результат:** клиент архивной погоды для двух турбин. Он получает 48 последовательных почасовых значений из конкретного запуска ECMWF IFS HRES 9 км, сохраняет момент решения и URL запроса, проверяет отсутствие пропусков и кеширует ответ.

**Как проверить первый шаг:**

```sh
python3 forecast_weather.py 2026-02-01
```

Ожидается по одной строке для каждой турбины с `48 hours` и временем запуска `2026-01-31T18:00:00Z`. В `weather-cache/` появятся два JSON. Повтор команды использует кеш. Ошибочная дата (`python3 forecast_weather.py bad-date`) завершается кодом 1.

**Факт проверки:** 23.09.2026 обе турбины вернули по 48 часов; первый результат [опубликован в 13:36, коммит 3d9333c](https://github.com/BAITC-Hacks/hack-c04b1cb2-m-m-s/commit/3d9333ca17949be6b615628c300887153dafdf57). Типичная задержка публикации глобального погодного запуска 4–6 часов, поэтому решение в 06:00 UTC использует запуск предыдущего дня 18:00 UTC с 12-часовым запасом. Точное время доступности каждого запуска отдельно не подтверждено.

**Развитие до конца часа:** локально добавлены обучение кривой мощности, январская оценка, полный ежедневный цикл за 31.01–28.02, модельные артефакты и веб-интерфейс. Проверено 29 × 48 прогнозных часов. Эти изменения сохранены отдельным локальным коммитом `7b08588`; опубликованный первый результат остаётся доступен по ссылке выше.

## Второй час, работа к 15:00

**Уже выполнено локально:** исходная модель проверена на всём январе; масштаб прогнозного ветра ×1,10 выбран по 1–14 января и проверен на 15–31 января. На отложенных 408 часах MAE снизилась с 0,1608 до 0,1477 для турбины 1 и с 0,1654 до 0,1518 для турбины 2. Поправка включена только в февральскую модель. Полные цифры и ограничения — в [docs/VALIDATION.md](docs/VALIDATION.md).

Сохранены 29 ежедневных прогнозов по 48 часов в [results/](results/) и один [CSV на 672 часа февраля](results/february-hourly.csv), где для каждого часа выбран последний уже доступный прогноз. `python3 export_results.py` повторно собрал CSV и подтвердил полное покрытие. Локальный интерфейс показывает сохранённые результаты без интернета; кнопка повторного расчёта заново запрашивает погодный архив. Обе ветки API проверены на 1 февраля, они дали одинаковые 48 значений. Папка без погодного кеша смогла открыть сохранённый прогноз на 28 февраля.

**Публикация:** пользователь разрешил push, и [коммит 1a357a9](https://github.com/BAITC-Hacks/hack-c04b1cb2-m-m-s/commit/1a357a9c7c2c47997e6cc0c77964e4b9bc077f85) появился в официальном репозитории до 14:19. `gh api` подтвердил этот SHA как `main`. Из свежего клона без погодного кеша запущен локальный интерфейс; 28.02 открылся с 48 часами, а пересобранный CSV побайтно совпал с опубликованным.

[Дополнительный коммит 3a93da5](https://github.com/BAITC-Hacks/hack-c04b1cb2-m-m-s/commit/3a93da5d182b4f09a1273f376ae68f5389d70a39) добавил схему автономного цикла и проверки сохранённой погоды и ежедневных результатов. После этого в локальную демонстрацию добавлена ссылка на скачивание CSV; ответ сервера содержит 672 строки данных.

По просьбе пользователя в репозиторий добавлены подготовленные роли Codex из `.codex/`. В [разделе «Заготовки» README](README.md#заготовки) и [реестре происхождения](docs/PREPARED.md) отдельно обозначены четыре файла, созданные до 13:00, и специализированная роль, созданная в 14:11. Прогнозная модель и данные результатов этими заготовками не подменяются.

## Демонстрация текущего сквозного сценария

```sh
python3 web.py
```

Открыть `http://127.0.0.1:8000/`, выбрать 1 февраля 2026 и нажать «Рассчитать». Появятся 48 строк, график двух турбин и среднего, время погодного запуска и анализ. Нужны Python 3.10+ и интернет при первом запросе; ключи и исходные CSV для демонстрации не нужны. Подробная команда CLI и ограничения — в [README.md](README.md).
